# Engineer Growth Roadmap

副業面接で**説明できなかったことを、説明・実装できる状態に変える**ためのリポジトリ。

## まずここから

学習を始めるときは、次の順番だけ確認する。

1. [現在地](progress.md#現在のサイクル)を開く
2. 「次の1アクション」を実行する
3. 下記の学習サイクルに従って記録する
4. 完了条件を満たしたら、次の面接へ進む

## 学習の型

```text
① 面接で現在地を測る
       ↓
② 回答をレビューする
       ↓
③ 🔴・🟡を1テーマだけ学ぶ
       ↓
④ 資料なしで再回答する
       ↓
⑤ Todo APIで確認・改善する
       ↓
⑥ 🟢判定してサイクルを閉じる
```

重要なのは、改善回答を読んで終わりにせず、必ず資料を閉じて再回答すること。

## ファイルの役割

| ファイル | 役割 | 更新するタイミング |
|---|---|---|
| [progress.md](progress.md) | 現在地・習熟度・次の1アクション | 毎回 |
| `sessions/*.md` | 自分の回答・レビュー・再回答 | 面接・復習時 |
| [`sessions/network/`](sessions/network/README.md) | ネットワーク問題演習・理解度・回答履歴 | ネットワーク学習時 |
| [portfolio.md](portfolio.md) | Todo APIの確認結果・改善候補・実装状況 | コード確認・実装時 |

`progress.md`以外には「現在のフォーカス」を書かない。現在地が分からなくなったら、必ず`progress.md`へ戻る。

## 1サイクルの完了条件

- [ ] 面接の回答を編集せずに残した
- [ ] 🔴・🟡から最優先テーマを1つ選んだ
- [ ] 定義・目的・比較・実務例を学んだ
- [ ] 資料を閉じて再回答した
- [ ] Todo APIとの関連を確認した
- [ ] 評価と`progress.md`を更新した

## 面接記録の型

各質問には次を順番に記録する。

```markdown
## Q1. 質問

### 初回回答
### 回答時に自信がなかった点（任意）
### フィードバック
### 学習した要点
### 再回答
### 最終評価
### Todo APIとの関連
```

自己評価は行わず、🔴・🟡・🟢はレビュー結果として付ける。回答者は必要に応じて、自信がなかった点だけを記録する。

## 評価基準

| 評価 | 状態 | 次の行動 |
|---|---|---|
| 🔴 | 説明できない、または誤りがある | 基礎から学習する |
| 🟡 | 概要は説明できるが、理由・実務例・深掘りに弱い | 不足部分を学び再回答する |
| 🟢 | 定義・理由・実務例を自分の言葉で説明できる | 完了。次のテーマへ進む |

「改善版を読める」「見ながら答えられる」は🟢にしない。

## 運用ルール

- 同時に学ぶテーマは1つ
- 同時に進めるTodo API改善も1つ
- 新しい面接へ進む前に、前回の最優先課題を1つ🟢にする
- 学習メモの量ではなく、再回答できたかで完了を決める
- AIは回答の代筆ではなく、面接官・レビュアーとして使う
- ネットワーク問題は一度に5問ずつ追加し、回答前に模範解答を見ない

## 目標

- Spring Boot / React案件へ参画できる
- 月5〜10万円程度の副業を継続できる
- 自分の経験・設計・技術選定を面接で説明できる
